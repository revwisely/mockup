The method

How It Works

Seven steps. The rules and worksheets for every one of them ship as the markdown files in this kit.

01Scope what AI reads

Never boil the whole database. Name the workflow you want to run, then list only the fields and records it will actually read. Stale records exit the scope here, because archiving the dead beats scrubbing them. And every recurring obligation gets a name in the audit, because unowned cadences quietly stop.

02Measure the mess

Count it. Duplicates in scope, empty required fields, fields where two systems disagree, records untouched for a year. The before-number is the whole point. It makes the cleanup provable, and the re-measure gate reads against it.

03Dedupe by rule

Write merge rules before merging anything. Which record survives, and for each field, which source wins. Rules mean the dedupe never gets done by hand twice, and next quarter's duplicate meets the same rules instead of a new argument.

04Prune dead fields

Run the field census. For every custom field in scope, who filled it last, when, and what reads it. Unused and duplicated fields are noise, and AI will faithfully read the noise.

Watch for the field someone quietly reports from. The census asks before it deletes.

05Fix at the source

Cleanup without entry validation refills the mess on a schedule, which is why this step ships its own worksheet. Entry points, field-by-field treatments, picklist conversions, each with an owner. The test for any rule: it makes tomorrow's records cheaper to trust without making them slower to create.

06Guard the writes

Fail loud, never plausible. A deterministic check hits a wrong field and throws an error you see. A model hits the same wrong field, adapts, and writes something plausible anyway. Silence is the failure mode. Three guards before any tool writes: loop protection, a do-not-touch list covering records AND fields, honored at every write path with merges included, and deterministic validation around every AI write.

07Re-measure and gate

The before-number must move. Re-run the step 02 counts, with the conflict sample freshly drawn at random, never the records you fixed. Until the numbers move, no workflow reads these records. A gate that reads a number cannot be argued with.

Starting points, not laws. Set yours before the cleanup and write down why; thresholds set after the work always equal whatever the work achieved. Count rows re-run monthly. Guard rows re-test on change, and any new integration reopens the do-not-touch row.
