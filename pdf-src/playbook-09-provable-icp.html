The method

How It Works

Seven steps. The runnable versions ship as the markdown files in this kit.

01Write the ICP as one verdict field

Routing reads one field per account, so write the ICP as that field. Four values. Fit, marginal, no_fit, and unknown, for a missing source, two sources that disagree, or a verdict that flipped. Each rule names the page that checks it, so a stranger gets your answer. Fit and intent stay in separate fields.

VerdictWhat it meansRouting
fitevery checkable rule passes, with a source for eachTier 1, a person
marginalnear the rules, a real company where the offer could landTier 2, a sequence
no_fitwrong kind of entity, or a rule plainly failsnothing, reason kept
unknowna source missing, sources in conflict, or a flipits own queue, an owner

Watch for the missing fourth value. Without unknown, a thin account gets forced into a tier, and the guess routes like a fact.

02Label a golden set blind

Twenty to thirty accounts drawn from where your routing draws, with clear no_fits and hard cases mixed in on purpose. A person labels each one against the written definition before seeing any agent output. Unknown is a valid label. A blank cell is an error.

03An agent returns one sourced verdict

Only the name and domain go in. The agent finds each rule's value on the web, with the page and its date, and returns fixed JSON. A short check runs before the CRM reads it. A fit missing a source drops to unknown, and so does stale evidence.

04Check agreement against the labels

Score the agent on the golden set. Read every disagreement by hand and fix the prompt, the rule, or the label. Accept a run, call its agreement the baseline, and set the threshold about 0.15 under it. A run that scores fewer accounts than the minimum is unreadable, and unreadable fails.

Watch for a threshold at the baseline. It fails on ordinary noise and gets ignored within a month.

05Check that the verdict holds still

A backtest runs once, so it never sees a verdict change. Run the golden set three times, then once on a second model. A verdict that flips goes to unknown with the reason "unstable", even when most runs agreed. The flipped accounts usually share one rule, and that rule gets rewritten.

06Route by tier, with unknown as its own queue

Code maps verdicts to the tiers in the table on the previous page. The model never picks a channel. The unknown queue has a named owner who works it. Every verdict is appended to a dated log, because the readout in step 07 needs the verdict that was in force, and a re-score overwrites the current one.

07Read outcomes by the tier that routed them

Monthly, credit each meeting, opportunity, win and loss to the verdict in force before the month opened. Under ten accounts, the cell prints a refusal in place of a rate. If you hold a declared and an evidenced profile, score both until the readout picks one.

Widen, Hold, or Pull Back

Written before the first readout, so the readout decides. Read only at or above the minimum count.

The readout showsDecision
Tier 1 converts clearly above Tier 2Hold. The tiering works
Tier 2 matches Tier 1 for two months runningWiden. Tier 2 gets Tier 1 treatment
Tier 1 converts no better than Tier 2 for two monthsPull back. Rework the definition
Unknown holds more outcomes than any tierWork the unknown queue. The rules miss the buyers
Every rate refusesKeep recording. Decide nothing yet

The terms, as this kit uses them

  • Baseline. The agreement of the run a person read and accepted.
  • Minimum count. Below it the run is unreadable, and unreadable fails.
  • Flip. A verdict that changed across three runs or a second model.
  • Verdict in force. The last verdict logged before the month opened.
  • Covered-through date. Every outcome up to this day is entered.
